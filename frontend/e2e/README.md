# E2E testing (Playwright)

Automated browser suites against the local app. Prerequisites:

1. Backend API on `:3001` (e.g. `cd backend && npm run start:dev`).
2. Frontend on `:3000` (e.g. `cd frontend && npm run dev`).
3. Playwright chromium installed: `npx playwright install chromium`.

## Suites

| File | What it covers |
| --- | --- |
| `a11y.spec.ts` | axe-core WCAG 2.1 A/AA scan of 12 public routes |
| `responsive.spec.ts` | no horizontal overflow across 5 breakpoints × 5 public pages |
| `ui-features.spec.ts` | institutional subcategory tabs, theme switcher, auction-type cards |
| `dashboard.spec.ts` | authenticated admin dashboard smoke (session via storageState) |

## Run

```bash
cd frontend
npx playwright test              # everything (setup + public + auth'd)
npm run test:a11y                # a11y suite only
npx playwright test e2e/ui-features.spec.ts
```

Set `A11Y_BASE_URL` to target a different origin (default `http://localhost:3000`).

## Authentication

The cookie-consent banner is pre-accepted for all runs via the static storageState
`playwright/.auth/public.json`. The authenticated project uses
`playwright/.auth/admin.json`, which is generated by logging in as the admin test
account. If it is missing (or the session expires), regenerate it:

```bash
cd frontend
node scripts/_make-auth.js
```

Then re-run `npx playwright test`.

## Notes

- Traces on failure: `test-results/*.zip` → `npx playwright show-trace <zip>`.
- Public suites run anonymously (separate `chromium-public` project) so the scans
  match the unauthenticated experience.
